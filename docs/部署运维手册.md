## 2. 构建产物

### 2.1 后端

```bash
# 全量构建（跳过测试时须谨慎，见第 6 节）
mvn -U clean package -DskipTests

# 单服务构建
mvn -pl xftt-article -am package -DskipTests
```

产物位置：`{模块}/target/{artifactId}-1.0-SNAPSHOT.jar`

可独立运行的模块：xftt-login、xftt-user、xftt-article、xftt-behavior、xftt-media、xftt-admin、xftt-crawler、xftt-images、xftt-migration、xftt-gateway。
公共库（common / utils / apis / model）为依赖，不产出可执行包。

### 2.2 前端

```bash
cd xftt-web/xftt-wemedia && npm ci && npm run build   # dist/
cd xftt-web/xftt-admin   && npm ci && npm run build   # dist/
cd xftt-web/xftt-app     && npm ci && npm run build:h5 # dist/build/h5/
```

前端构建已内置 `vue-tsc --noEmit`（wemedia / admin），类型错误会导致构建失败。

## 3. 启动与停止

### 3.1 启动命令

```bash
# 指定 Nacos 地址与命名空间（推荐外置，不写死在包内）
java -jar xftt-article-1.0-SNAPSHOT.jar \
  --spring.cloud.nacos.discovery.server-addr=192.168.20.130:8848 \
  --spring.cloud.nacos.config.server-addr=192.168.20.130:8848 \
  --spring.cloud.nacos.config.namespace=xftt \
  --spring.profiles.active=prod
```

### 3.2 启动顺序

1. Nacos → 2. MySQL / Redis / Kafka / ES → 3. 业务服务 → 4. 网关 → 5. Nginx

### 3.3 停止

优先优雅停机：向进程发送 `SIGTERM`，等待处理中的请求结束（默认 30s）后再 `kill -9`。

---

## 4. 配置外置原则

1. **敏感信息不入库**：数据库账号、Redis 密码、第三方 AK/SK 只放 Nacos 配置集或启动参数，禁止写入 `application.properties` 提交。
2. **环境隔离**：用 Nacos 命名空间区分 dev / test / prod，与 `spring.profiles.active` 保持一致。
3. **端口统一**：端口定义在 `xftt-common/src/main/resources/config/application.properties`，新增服务必须在此登记，禁止散落。
4. **覆盖优先**：本地 `application.properties` 只保留「连接 Nacos」所需的最小配置，其余全部来自配置中心。

## 5. 健康检查与监控

| 组件 | 检查方式 | 期望 |
|---|---|---|
| 网关 | `GET /actuator/gateway/routes` | 返回全部服务路由 |
| 各服务 | `GET /actuator/health` | `{"status":"UP"}` |
| Nacos | 控制台「服务管理 → 服务列表」 | 实例数与健康实例数一致 |
| 前端 | `curl -I http://<域名>` | 200 |

网关已开放 `gateway` 与 `health` 端点（只读）；其余服务的 actuator 端点待统一开启并做鉴权。

## 6. 发布流程

1. **门禁**：后端 `mvn compile` 通过；前端 `vue-tsc --noEmit` + `build` 通过。
2. **打标签**：按 [开发规范](./开发规范.md) 从 `dev` → `test` → `main`。
3. **构建**：CI 执行 `mvn package` 与 `npm run build`，产出物归档。
4. **灰度**：先发布 1 台，观察 10 分钟日志与 health 端点。
5. **全量**：滚动重启，每批间隔 ≥30s。
6. **回归**：按 [需求文档 第 14 章验收流程](./需求文档.md) 抽查核心链路。
7. **回滚**：保留上一版本产物，回滚只需替换 jar 并重启。

## 7. 故障排查速查

| 现象 | 排查路径 |
|---|---|
| 服务在 Nacos 中不可见 | 检查 `server-addr`、`namespace`、用户名密码；查看服务日志中 Nacos 连接异常 |
| 网关 404 | 确认访问路径为 `/{小写服务名}/{原路径}`；查 `/actuator/gateway/routes` 是否含目标服务 |
| 接口 401/403 | 核对 JWT 是否有效、Token 过滤器是否放行白名单路径 |
| 配置修改不生效 | 确认 `spring.config.import` 的 Data ID 与服务名一致，且 `refreshEnabled=true` |
| 数据库连接池耗尽 | 检查慢查询与连接泄漏；确认 MyCat 8066 连通 |
| Kafka 消息堆积 | 检查消费者组 lag；确认 images / migration 消费者在线 |
| 前端白屏 | 检查 Nginx 静态资源路径与 history 路由 fallback 配置 |

## 8. 备份与恢复

| 对象 | 方式 | 频率 |
|---|---|---|
| MySQL | `mysqldump` 全量 + binlog 增量 | 每日全量，binlog 实时 |
| Nacos 配置 | 配置集导出为 SQL / ZIP | 每次变更后 |
| 素材文件（FastDFS） | 存储目录快照 | 每周 |
| 构建产物 | 版本化归档 | 每次发布 |

恢复演练要求：每季度至少一次，验证全量脚本可在空库上重建（`bak.sql` 仅作历史比对，不作为恢复源）。
