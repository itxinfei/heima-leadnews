## 8. 对象存储方案变更记录（MinIO AIStor → RustFS）

- 背景：共享栈原 MinIO 使用 AIStor 商业镜像（`quay.io/minio/aistor/minio:RELEASE.2026-06-06T02-44-06Z`），无许可证时全部管理/匿名操作返回「No license is installed」；社区版镜像在所有可达 registry 与镜像源均不可获取（Docker Hub denied、quay 401、dl.min.io 410、GitHub 404 等）。
- 变更：共享栈改用 **RustFS**（S3 兼容，无授权门槛），镜像 digest 钉死，容器名/端口/凭据/数据目录语义保持不变。
- 影响：应用零改造（MinIO Java SDK 直连 S3 协议）；管理端无 `mc`，改用 `scripts/s3_public_bucket.py`（纯 stdlib）。
- 备注：手册 §2 的 MinIO 版本条目与当前运行时不一致（RustFS 替代），已在本文记录，**手册本身未改动**；如需回填手册请另行确认。

## 9. 风险与回滚

| 风险 | 应对 |
|---|---|
| RustFS 与 MinIO SDK 的兼容性边界 | 已验证签名读写/匿名读；上线后关注分片上传、预签名 URL |
| Nacos 超管/自建账号直连 | 开发期可接受；如需最小权限再开用户管理 |
| HBase 数据未持久化 | 冷迁移前按需加 `hbase-data` 卷 + `hbase.rootdir` |
| Kafka 宿主端口映射 9092→9094 | 应用配置用宿主 `:9092`，已验证 |
| 共享栈升级导致配置漂移 | 只依赖标准端口与手册凭据；变更后重跑 verify 脚本 |

**回滚**：`docker compose -f ~/xftt-middleware/docker-compose.yml down`（HBase）；Nacos 删除命名空间 `xftt` 或重置 9 个 Data ID；对象存储删除桶 `xftt`（仅我们自己的桶）。
