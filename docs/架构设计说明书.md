# 心飞头条（xftt）架构设计说明书

> 维护者：心飞团队　　最后更新：2026-10-23　　基线：master @ 067bf2b2

---

## 1. 架构总览

心飞头条采用**前后端分离 + 微服务**架构。三端统一通过网关入口访问后端，服务注册与配置中心使用 Nacos，网关基于服务名自动路由，业务服务之间通过 Feign 调用。

```
┌────────────┐  ┌──────────────┐  ┌──────────────┐
│  xftt-app  │  │ xftt-wemedia │  │  xftt-admin  │
│ uni-app V3 │  │ Vue3 + EP    │  │  Vue3 + EP   │
└─────┬──────┘  └──────┬───────┘  └──────┬───────┘
      └────────────────┼─────────────────┘
                       ▼
        ┌────────────────────────────────┐
        │  xftt-gateway : 10000       │
        │  SCG 5 + Nacos Discovery 自动路由│
        └───────────────┬────────────────┘
        ┌───────┬───────┼───────┬───────┬────────┐
        ▼       ▼       ▼       ▼       ▼        ▼
      login   user   article behavior media   admin
                                │
                                ├── images（Kafka 消费）
                                ├── crawler（Quartz 调度）
                                └── migration（Quartz 任务）
```

### 1.1 技术选型

| 层次 | 技术 | 版本 | 说明 |
|---|---|---|---|
| 运行时 | JDK | 25 | 后端统一基线 |
| 基础框架 | Spring Boot | 4.1.1 | 父工程继承 `spring-boot-starter-parent` |
| 微服务 | Spring Cloud | 2025.1.3 | 网关、OpenFeign、LoadBalancer |
| 网关 | Spring Cloud Gateway | SCG 5 | 配置前缀 `spring.cloud.gateway.server.webflux` |
| 注册/配置 | Nacos | 3.x | 命名空间 `xftt` |
| 持久层 | MyBatis | 3.5.19 | Mapper XML 集中在 xftt-model |
| 数据库 | MySQL | 9.7.0 | 经 MyCat 分库分表访问（8066） |
| 缓存 | Redis | — | 热点文章、登录态、分布式锁 |
| 搜索 | Elasticsearch | 9.4.5 | 文章检索、联想词 |
| 消息 | Kafka | 4.2.1 | 行为上报、文章上下架 |
| 实时计算 | Kafka Stream | — | 热点文章流式聚合（xftt-migration） |
| 文件存储 | FastDFS | — | 素材图片 |
| 前端 · APP | uni-app + Vue 3 + Pinia + wot-design-uni | 3.x | `xftt-web/xftt-app` |
| 前端 · 后台 | Vue 3 + Vite + TS + Element Plus + Axios | — | wemedia / admin |

## 2. 工程结构

父工程 `com.xftt:xftt`（packaging=pom）下分 **4 个公共库** 与 **11 个可运行服务**。

```
xftt/
├── xftt-common     公共配置与横切能力（不可独立运行）
├── xftt-utils      工具类（加解密、JWT、ThreadLocal、雪花 ID）
├── xftt-apis       Feign 接口契约
├── xftt-model      DTO / POJO / Mapper 接口与 XML
├── xftt-login      登录注册
├── xftt-user       用户关系
├── xftt-article    文章、频道、评论、搜索
├── xftt-behavior   行为采集
├── xftt-media      自媒体端
├── xftt-admin      平台后台
├── xftt-crawler    爬虫
├── xftt-images     图片服务
├── xftt-migration  数据迁移与热点计算
├── xftt-gateway 网关（:10000）
└── xftt-mycat   分库分表中间件（:8066）
```

### 2.1 公共库职责

| 模块 | 关键内容 |
|---|---|
| xftt-common | `redis`、`kafka`、`kafkastream`、`elasticsearch`、`fastdfs`、`hbase`、`mongo`、`mysql`、`quartz`、`zookeeper`、`jackson`、`threadpool`、`web`（全局异常与统一响应）、`admin`（鉴权过滤器）、`aliyun`（OCR/人脸） |
| xftt-utils | `MD5Utils`、`DESUtils`、`Base64Utils`、`AppJwtUtil`、`SnowflakeIdWorker`、`SimHashUtils`、`UrlSignUtils`、`BurstUtils`（分库分表路由）、`{App,Wm,Admin}ThreadLocalUtils` |
| xftt-apis | 按服务分包：`admin/apis`、`article/apis`、`behavior/apis`、`images/apis`、`login/apis`、`media/apis`、`user/apis` |
| xftt-model | 实体与 Mapper，XML 位于 `xftt-model/src/main/resources/mappers/{admin,app,crawerls,wemedia}/` |

### 2.2 模块依赖规则

1. 业务服务 **只能** 依赖公共库，禁止服务间直接依赖（跨服务调用走 `xftt-apis` 的 Feign 接口）。
2. `xftt-model` 不依赖任何业务服务；`xftt-common` 可依赖 `xftt-utils`。
3. 公共库之间禁止循环依赖。

## 3. 分层设计

以 `xftt-article` 为例，标准四层：

```
Controller（xftt-article/controller/v1|v2）
    │  只做参数接收与结果封装，不做业务
    ▼
Service / ServiceImpl（service/impl）
    │  业务编排、事务控制、缓存与消息投递
    ▼
Mapper（xftt-model/mapper）+ XML（xftt-model/resources/mappers）
    │  仅负责 SQL
    ▼
MySQL / ES / Redis / HBase / Mongo
```

**约定**
- Controller 不允许直接访问 Mapper。
- Service 不得感知 HTTP 对象（`HttpServletRequest` 等）。
- 统一响应体 `ResponseResult<T>`：`{code, errorMessage, data}`，成功 `code=0`。
- 统一前缀 `/api/{version}/{module}`，网关按服务名小写转发。
- v1 与 v2 并存：v2 为新版契约，前端优先接 v2，v1 保留兼容。

## 4. 核心调用链

### 4.1 用户浏览信息流

```
APP 首页 → POST /api/v1/article/load
         → gateway → xftt-article
         → ApArticleMapper（MyCat 分片查询）
         → 返回 ResponseResult<PageResult>
         → 卡片曝光 → POST /api/v1/behavior/show_behavior（异步）
```

### 4.2 阅读与互动

```
详情打开 → /api/v1/article/load_article_info（正文）
        → /api/v1/article/load_article_behavior（点赞/收藏/阅读数回显）
点赞操作 → /api/v1/behavior/like_behavior {operation: 0|1}
评论     → GET  /api/v1/comment/list
        → POST /api/v1/comment/create
        → POST /api/v1/comment/like
```

### 4.3 搜索

```
输入联想 → POST /api/v1/article/search/associate_search
发起搜索 → POST /api/v1/article/search/article_search（ES）
历史记录 → load_search_history / del_search / clear_search
热词     → load_hot_keywords
```

### 4.4 内容生产与审核（当前 P0，待补发布闭环）

```
自媒体端登录 → POST /login/in（xftt-media）
素材上传     → POST /api/v1/media/material/upload_picture（FastDFS）
文章提交     → POST /api/v1/media/news/submit
             → 自动审核（文本 + 图片）
             → 审核通过 → Kafka 下发 → xftt-article 落库 + 建 ES 索引
             → 审核驳回 → 状态回写，自媒体端可见
后台人工审核 → /api/v1/admin/common/{list,update,delete}
```

### 4.5 热点计算与冷热分离（M6，规划中）

```
行为上报 Kafka → Kafka Stream（10 分钟窗口聚合，xftt-migration）
              → ApHotArticles（热点库）
              → 定时迁移：MySQL 冷数据 → HBase，热点数据 → Mongo
```

## 5. 数据架构

### 5.1 库表分组

| 前缀 | 归属 | 代表表 | Mapper XML 目录 |
|---|---|---|---|
| `ap_` | APP 端 | ap_article、ap_user、ap_comment、ap_behavior_entry | `mappers/app` |
| `wm_` | 自媒体端 | wm_user、wm_news、wm_material、wm_news_statistics | `mappers/wemedia` |
| `ad_` | 平台后台 | ad_user、ad_channel、ad_channel_label、ad_label | `mappers/admin` |
| `cl_` | 爬虫 | cl_news、cl_news_comment、cl_ip_pool、cl_news_additional | `mappers/crawerls` |

> 完整规范见 [心飞头条-数据库规范设计说明书](./心飞头条-数据库规范设计说明书.md)。

### 5.2 分库分表

- 中间件：MyCat（`xftt-mycat:8066`），自定义热点分片算法 `XfttBurstRuleAlgorithm`。
- 路由工具：`xftt-utils` 的 `BurstUtils`，负责生成分片键的 burst 值。
- 分片表：行为类大表（`ap_*_behavior`）与文章表，按业务主键分片。

### 5.3 缓存与检索

| 数据 | 存储 | 用途 |
|---|---|---|
| 热点文章列表 | Redis | 首页与热点频道毫秒级响应 |
| 文章正文与历史 | MySQL → HBase（冷） | 冷热分离（M6） |
| 文章检索索引 | Elasticsearch | 关键词搜索与联想词 |
| 素材图片 | FastDFS | 自媒体素材库 |

## 6. 横切能力

| 能力 | 实现位置 | 说明 |
|---|---|---|
| 统一响应与全局异常 | `xftt-common/web` | Controller 抛业务异常后统一转 `ResponseResult` |
| 登录鉴权 | `xftt-common/admin` 过滤器 + `AppJwtUtil` | APP 用 JWT；后台/自媒体用 Token 过滤器 |
| 线程上下文 | `{App,Wm,Admin}ThreadLocalUtils` | 存放当前登录用户，请求结束必须清理 |
| 分布式 ID | `SnowflakeIdWorker` / `IdsUtils` | 禁止数据库自增主键暴露给外部 |
| 异步与线程池 | `xftt-common/threadpool` | 统一线程池，禁止业务自行 `new Thread` |
| 加签验签 | `UrlSignUtils` | 网关侧 sign 校验（BE-F10 待统一） |

## 7. 关键设计决策

| 决策 | 选择 | 理由 |
|---|---|---|
| 版本号 | `4.1.1` | JDK 25 兼容基线，避免停留在已停止维护的 2.x |
| 网关配置前缀 | `spring.cloud.gateway.server.webflux` | SCG 5 强制新前缀，旧前缀已废弃 |
| 包名 | `com.xftt` | 统一品牌标识，与旧 `com.xinfei` 彻底切割 |
| 前端 APP | uni-app + Vue 3 | 一套代码覆盖 H5/小程序/App，改造成本最低 |
| 配置外置 | Nacos 命名空间 `xftt` | 本地仅保留启动必要项，敏感配置不入库 |
| Mapper XML 集中 | xftt-model | 避免 XML 与接口分散在多服务，便于统一 review |

## 8. 已知架构风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 各服务 `application.yml` 主要托管在 Nacos，本地无副本 | 无 Nacos 时服务无法启动 | 见 [环境搭建与启动指南](./环境搭建与启动指南.md)「离线兜底配置」 |
| 网关鉴权未统一（sign + token 各自实现） | 三端安全策略不一致 | BE-F10：统一鉴权过滤器 |
| v1/v2 接口并存 | 前端调用易混用 | 新页面一律接 v2，v1 仅兼容存量 |
| `ap_comment` 表未建 | 评论接口运行时报错 | BE-F01：补建表与初始化脚本 |
| 前端评论/行为依赖 `equipmentId`，当前传 0 | 行为数据无法关联设备 | 联调时接入设备注册接口（ApEquipment） |
