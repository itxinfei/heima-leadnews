# 心飞头条（xftt）开发规范

> 维护者：心飞团队　　最后更新：2026-10-23
> 适用范围：本项目全部 Java 后端、前端（Vue3/TS）代码与文档。

---

## 1. 编码前强制动作

编写任何代码前，必须先确认三件事：

1. **复用检查**：Java 查 xftt-common / xftt-utils / xftt-model 是否已有可用实现；前端查 src/utils、src/api、src/components 是否已有同类封装。**禁止重复造轮子**。
2. **依赖申报**：新增第三方依赖必须在 PR/提交说明中写明用途与替代方案评估。
3. **契约同步**：新增或修改接口，须同日更新 `docs/接口清单.md`；涉及表结构须同日更新数据库规范文档。

## 2. Java 规范

### 2.1 命名

| 元素 | 规则 | 示例 |
|---|---|---|
| 包名 | 全小写，前缀 com.xftt | `com.xftt.article.controller.v1` |
| 类名 | PascalCase | `ArticleHomeController` |
| 方法/变量 | camelCase | `loadArticleList` |
| 常量 | UPPER_SNAKE_CASE | `MAX_PAGE_SIZE` |
| Mapper XML | 与接口同名 | `ApArticleMapper.xml` |

### 2.2 结构约束

- 文件编码 UTF-8，**无 BOM**。
- 单行 ≤ 120 字符；单方法 ≤ 80 行；嵌套 ≤ 3 层。
- Controller 只做参数接收与响应封装，**禁止写业务、禁止直接调 Mapper**。
- Service 层负责业务编排与事务，Mapper 层只写 SQL。
- Mapper XML 统一放在 `xftt-model/src/main/resources/mappers/`。

### 2.3 安全（强制）

- **SQL 注入**：一律使用 MyBatis `#{}`，禁止 `${}` 拼接；确实需要动态列时走白名单校验。
- **XSS**：输出到前端的富文本用 `HtmlUtil.escape()` 处理后再返回。
- **敏感信息**：密钥、数据库账号只允许存在于 Nacos 配置或启动参数，**禁止硬编码进仓库**。
- **文件路径**：禁止用户可控路径直接拼接访问文件系统。
- **参数校验**：Controller 入参必须校验（非空、长度、枚举范围），不允许裸接收。

### 2.4 异常与日志

- 使用 SLF4J（`lombok.extern.slf4j.Slf4j`），**禁止 System.out.println**。
- 捕获**具体异常**，禁止 catch (Exception e) 一把梭。
- 每个 catch 块必须输出带上下文的日志（函数名、关键参数），禁止空 catch。
- 日志禁止输出密码、Token、身份证等敏感字段。

```java
@Slf4j
@Service
public class ArticleServiceImpl implements ArticleService {
    @Override
    public ResponseResult<List<ApArticle>> load(ArticleHomeDto dto) {
        try {
            return ResponseResult.okResult(apArticleMapper.loadArticleList(dto));
        } catch (DataAccessException e) {
            log.error("查询文章列表失败, dto={}", dto, e);
            return ResponseResult.errorResult(AppHttpCodeEnum.SERVER_ERROR);
        }
    }
}
```

### 2.5 注释与文档

- 所有类、public 方法必须有 JavaDoc，说明用途、参数、返回值、异常。
- 修改既有代码时，改动处标注 `// 修改点：<说明>`。
- 接口变更同步更新 Swagger 注解与 `docs/接口清单.md`。

### 2.6 测试

- 使用 JUnit；核心业务逻辑覆盖率目标 100%，整体 ≥ 80%。
- 必须覆盖异常分支（参数非法、依赖不可用、空结果）。

## 3. 前端规范（Vue 3 + TS）

### 3.1 组件与文件

- 组件命名 PascalCase，单文件组件按 script setup lang="ts" + template + style scoped 三段组织。
- props 必须声明类型与默认值。
- 列表渲染必须绑定唯一 key，禁止用 index。
- 复杂展示逻辑放入 computed，禁止在模板里写长表达式。
- 样式一律 scoped，公共变量统一在主题文件中维护。

### 3.2 接口与状态

- 所有请求集中在 `src/api/`，路径统一 `/api/v1/...`。
- Axios 全局拦截器统一处理错误与弹窗提示，页面层不重复写 try/catch toast。
- 登录态不永久存储，localStorage 必须带过期时间。
- **禁止未经清洗的内容使用 v-html**。
- 非核心接口（频道、评论、行为上报）失败必须静默降级，不得阻塞主流程。

### 3.3 类型与构建

- 提交前必须通过 `vue-tsc --noEmit`。
- 禁止滥用 any；对象形状未知时用 unknown 并做类型守卫。
- 三端构建零错误方可入库。

## 5. 分支与提交

### 5.1 分支模型

```
main（线上）
 └─ test（测试）
     └─ dev（开发）
         └─ feature/*（新功能）、fix/*（缺陷）
```

分支命名示例：`feature/APP-F11-search`、`fix/env-proxy-port`。

### 5.2 提交信息格式

```
<type>: <简短描述>

type 取值：
  feat     新增功能
  fix      修复缺陷
  docs     文档更新
  style    格式调整（不影响逻辑）
  refactor 重构
  test     测试相关
  chore    构建/依赖/杂项
```

### 5.3 禁止入库

`.log`、`target/`、`node_modules/`、`dist/`、`.idea/`、`.pyc`、临时脚本与缓存文件。
新增忽略项须同步更新 `.gitignore`。
