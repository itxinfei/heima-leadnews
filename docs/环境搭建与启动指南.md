# 心飞头条（xftt）环境搭建与启动指南

> 维护者：心飞团队　　最后更新：2026-10-23　　基线：master @ 067bf2b2
> 适用系统：Windows 11（Linux/macOS 仅命令写法不同，步骤一致）

---

## 1. 依赖清单

### 1.1 必装（后端编译 + 启动）

| 组件 | 版本 | 用途 | 校验命令 |
|---|---|---|---|
| JDK | 25 | 后端运行时 | `java -version` |
| Maven | 3.9+ | 构建 | `mvn -v` |
| MySQL | 9.7.0 | 主库 | `mysql -V` |
| Nacos Server | 3.x | 注册 + 配置中心 | 浏览器访问 `:8848/nacos` |
| Redis | 6+ | 缓存、登录态、分布式锁 | `redis-cli ping` |
| Node.js | 18 LTS+ | 前端构建（Vite 5 要求 ≥18） | `node -v` |

### 1.2 按需启用

| 组件 | 版本 | 影响的模块 | 不装时的表现 |
|---|---|---|---|
| Kafka | 4.2.1 | behavior、article、images、migration | 行为上报与热点计算不可用，主流程可跑 |
| Elasticsearch | 9.4.5 | article 搜索 | 搜索相关接口失败 |
| FastDFS | — | media 素材上传 | 素材上传失败 |
| Zookeeper | — | crawler 调度 | 爬虫任务不可启动 |
| MongoDB | — | migration 热点存储 | 热点数据不落 Mongo |
| HBase | — | migration 冷数据 | 冷数据迁移不可用 |
| MyCat | 1.6+ | 分库分表 | 需改直连 MySQL 数据源 |

## 3. 首次搭建步骤

### 3.1 拉取代码

```bash
git clone <仓库地址> heima-leadnews
cd heima-leadnews
```

### 3.2 初始化数据库

```bash
# 创建数据库后导入全量脚本
mysql -u root -p < xinfei-leadnews.sql
```

- 全量脚本：`xinfei-leadnews.sql`（仓库根目录）
- 补充脚本：`docs/数据库脚本.rar`（解压后按需导入）
- `bak.sql` 为历史备份，**仅供比对，禁止导入生产**
- 表设计规范见 [数据库规范设计说明书](./心飞头条-数据库规范设计说明书.md)

> 修改点：评论相关接口依赖 `ap_comment` 表，若脚本中缺失需按 BE-F01 补建。

### 3.3 启动 Nacos

```bash
# 单机模式（Windows）
startup.cmd -m standalone
```

登录 `http://localhost:8848/nacos`，完成：

1. 创建命名空间 **xftt**，记录命名空间 ID。
2. 在 `xftt` 命名空间下创建配置文件（Data ID 与服务名一致）：

| Data ID | 分组 | 格式 | 内容 |
|---|---|---|---|
| `xftt-gateway.yml` | DEFAULT_GROUP | YAML | 路由、跨域、白名单 |
| `xftt-login.properties` | DEFAULT_GROUP | Properties | 数据源、Redis |
| `xftt-article.properties` | DEFAULT_GROUP | Properties | 数据源、Redis、ES、Kafka |
| `xftt-behavior.properties` | DEFAULT_GROUP | Properties | 数据源、Kafka |
| `xftt-user.properties` | DEFAULT_GROUP | Properties | 数据源 |
| `xftt-media.properties` | DEFAULT_GROUP | Properties | 数据源、FastDFS |
| `xftt-admin.properties` | DEFAULT_GROUP | Properties | 数据源 |
| `xftt-crawler.properties` | DEFAULT_GROUP | Properties | 数据源、ZK |
| `xftt-images.properties` | DEFAULT_GROUP | Properties | FastDFS、Kafka |
| `xftt-migration.properties` | DEFAULT_GROUP | Properties | 数据源、HBase、Mongo |

> Boot 4 已移除 bootstrap 机制，各服务通过
> `spring.config.import=optional:nacos:${spring.application.name}.properties?group=DEFAULT_GROUP&refreshEnabled=true`
> 显式导入，因此 **Data ID 必须与服务名完全一致**，否则配置不生效。

### 3.4 编译后端

```bash
mvn -U clean compile
```

若只需单模块：

```bash
mvn -pl xftt-article -am compile
```

### 3.5 启动后端服务

严格按以下顺序：

```bash
# 1. Nacos（先启动，否则后续服务配置拉不到）
# 2. 网关
mvn -pl service-gateway spring-boot:run

# 3. 业务服务（按需，建议先 login + article）
mvn -pl xftt-login spring-boot:run
mvn -pl xftt-article spring-boot:run
mvn -pl xftt-behavior spring-boot:run
mvn -pl xftt-user spring-boot:run
mvn -pl xftt-media spring-boot:run
mvn -pl xftt-admin spring-boot:run
```

### 3.6 启动前端

```bash
cd xftt-web

# APP（H5）
cd xftt-app && npm install && npm run dev:h5

# 自媒体端（http://localhost:8081）
cd xftt-wemedia && npm install && npm run dev

# 平台后台（http://localhost:8082）
cd xftt-admin && npm install && npm run dev
```

构建与类型检查：

```bash
npm run type-check   # 仅 APP
npm run build        # wemedia / admin（含 vue-tsc）
npm run build:h5     # APP H5 产物
```

## 4. 启动自检清单

| 检查项 | 方法 | 期望 |
|---|---|---|
| Nacos 服务列表 | 控制台「服务管理 → 服务列表」 | 各服务实例在线 |
| 网关路由 | `GET http://localhost:10000/actuator/gateway/routes` | 返回服务名路由 |
| 文章接口 | `POST http://localhost:10000/xftt-article/api/v1/article/load` | `code=0` |
| 频道接口 | `GET http://localhost:10000/xftt-article/api/v1/channel/list` | 返回频道数组 |
| 前端首页 | 浏览器打开 APP H5 地址 | 信息流正常渲染，无控制台报错 |
| 类型检查 | `vue-tsc --noEmit` | 零错误 |

> 网关开启了 `discovery.locator.enabled`，默认路由规则为
> `http://网关IP:10000/{小写服务名}/{原路径}`，例如
> `/xftt-article/api/v1/article/load`。

## 5. 离线兜底配置

Nacos 不可用时，可临时把占位符写回本地，避免服务无法启动：

1. 在 `xftt-common/src/main/resources/config/application.properties` 确认 `port.*`、`sn.*` 已定义。
2. 业务服务的 `application.properties` 中把
   `spring.config.import=optional:nacos:...` **临时注释**，并在同文件补上数据源与 Redis 配置。
3. **注意**：该文件属于公共库，改动后必须还原再提交；长期方案是补全 Nacos 配置集，而非改本地文件。

## 6. 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 启动时 `Could not resolve placeholder 'port.login'` | Nacos 上缺少对应 Data ID | 按 3.3 建配置集，或临时走第 5 节兜底 |
| 服务注册成功，但网关访问 404 | 路径未按 `/{服务名}/{路径}` 拼，或大小写不符 | 网关已开启 `lower-case-service-id`，服务名必须小写 |
| Nacos 控制台报鉴权失败 | 用户名/密码或命名空间不匹配 | 核对 `username=xinfei`、`namespace=xftt` |
| 编译报 Lombok 相关警告 | JDK 25 下 Lombok 版本兼容问题 | 编译可过；后续随 Lombok 升级消除 |
| 前端 8081 端口被占用 | wemedia dev server 与网关公共默认端口 8081 冲突 | 改 `vite.config.ts` 的 `server.port`，或让网关保持 10000 |
| 自媒体端/后台接口 404 | 旧代理目标 6002/6001 不存在，或 `baseURL: '/api'` 导致前缀冲突 | 已修复为按服务分流的 vite 代理（见第 7 节 ENV-01/04），并清空 `baseURL` |
| 评论接口运行报错 | `ap_comment` 表未建 | 执行 BE-F01 建表脚本 |

## 7. 已知待修项（联调前处理）

| 编号 | 问题 | 处理方案 |
|---|---|---|
| ENV-01 | wemedia 代理目标 `localhost:6002`、admin 代理目标 `localhost:6001`，与后端实际端口不符 | ✅ 已修复：dev 代理按服务分流——wemedia 全部走 `xftt-media:9006`；admin 的 `/api/v1/admin`、`/login` 走 `:9007`，频道管理 `/api/v1/channel/channels` 走 `xftt-media:9006`。前端 `baseURL` 已置空、`api.ts` 路径已对齐后端契约（见下 ENV-04）。统一网关路由配置好后可改回 `http://localhost:10000` |
| ENV-02 | 网关端口存在两个来源：本地 yml 为 10000，公共配置为 8081 | 统一以 10000 为准，清理公共配置中的 `port.gateway` |
| ENV-03 | 各服务 Nacos 配置集缺失 | ✅ 已出清单：`docs/Nacos配置集清单.md`（10 个 Data ID + 共享配置块），连接均指向 192.168.20.130。录入后服务即可拉到配置 |
| ENV-05 | MySQL 密码在 `MysqlCoreConfig.getRealPassword()` 中被反转后使用，Nacos 中 `mysql.core.jdbc.password` 需填反转串，易踩坑 | 建议改代码去掉反转，或在本清单第 6 节标注真实密码的反转值 |
| ENV-04 | 前端 api.ts 路径为旧黑马契约，与重构后 `xftt-*` 后端不符 | ✅ 已修复：wemedia/admin 的 `api/*.ts` 已对齐 `docs/接口清单.md`；管理端通用 CRUD 走 `/api/v1/admin/common`（CommonDto：`name`=枚举名 `AD_CHANNEL` 等、`model`=add/edit、`where`/`sets`）；**频道管理用 media 的 `/api/v1/channel/channels`**（返回完整 AdChannel 列表，已映射为 `{rows,total}`），不再用 article 的 `/api/v1/channel/list`（该接口只返回启用频道的 `{id,name}` 选项，供 APP 用）；登出改为**纯前端清空 localStorage token**（后端无 `/login/logout` 接口，无需后端）。前端 `baseURL` 置空 |
